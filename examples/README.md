# Architecture decision template

Use the CSV fields to document a decision before implementation. This is a reusable planning asset, not a runnable Next.js starter or a record of a real client project.

For a document assistant, a decision might concern whether to store embeddings in a managed database or an existing approved service. Record the problem, data classification, retrieval permissions, alternatives, chosen constraints and evidence required for acceptance. Include deletion behaviour and the operating owner.

Avoid decisions consisting only of a technology name. A useful record explains how the choice meets a requirement, what it makes more difficult and what would prompt reconsideration. Attach actual project evidence privately rather than putting customer documents or credentials in this public repository.

The [architecture guide](../docs/architecture-and-rendering.md) supplies a checklist and an illustrative diagram. This template can be reused without a cloud account or paid service.
